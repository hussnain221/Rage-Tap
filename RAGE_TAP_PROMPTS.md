## HOW TO USE THIS FILE

### Setup (human, before Prompt 0.1)
1. Put `RAGE_TAP_SPEC.md` and `RAGE_TAP_PROMPTS.md` in an empty folder, e.g. `rage_tap/`.
2. Install Flutter (stable) and Android Studio (Android SDK, platform-tools). Run `flutter doctor` and fix red items.
3. Phone: enable Developer options → USB debugging, connect by USB, accept the prompt. `adb devices` should list it. (If the agent can't see your phone, you run the `flutter run` commands yourself and paste errors back.)
4. Open the folder in Antigravity.

### Global rules (paste this as a Rules/Customization entry in Antigravity if available; otherwise paste it at the start of each new conversation)

```
You are building "Rage Tap", an offline Android one-tap arcade game with Flutter + Flame.
The file RAGE_TAP_SPEC.md in this folder is the single source of truth. Read the sections named in each task before coding.
Rules:
1. Do ONLY the current task. Never build features from later tasks.
2. Inspect the existing project before changing anything.
3. After each task run `flutter analyze` (must be clean) and `flutter test` (must pass) and summarize the files you created/changed and why.
4. Make the smallest change that works. Do not rewrite working code.
5. Use only the packages listed in the spec §3. Ask before adding any other.
6. Flame's API changes between versions: check the installed version's docs/source and use APIs that exist in it.
7. All art is drawn in code; sounds are generated by a script; no downloaded assets.
8. All tunable numbers live in lib/core/constants.dart. No magic numbers.
9. Commit after each task: "Prompt X.Y: <title>".
10. If something is unclear or conflicts with the installed packages, STOP and ask me.
```

### Prompt format
Each task has: **Spec** (sections to read), **Prompt** (paste this), **Done when** (acceptance), **Human check** (what you test).

### If something goes wrong (recovery prompts)
- **Build error:**
```
The build/analysis fails with this exact error: <paste full error>. The file involved is <file>. Fix only this error with the smallest change. Check the installed Flame/Flutter version's API rather than assuming. Explain the cause.
```
- **Behavior is wrong:**
```
Expected: <what should happen per SPEC §X>. Actual: <what happens>. Reproduce with seed <seed from the debug log>. Find the root cause first, explain it, then fix with the smallest change and add a test that would have caught it.
```
- **Agent over-engineered / changed too much:**
```
Revert to the last commit (git checkout . ; git clean -fd for untracked files from this task) and redo this task more minimally, touching only the files listed in the task.
```
- **Flame API mismatch:**
```
The code uses an API that doesn't exist in the installed Flame version <version from pubspec.lock>. Read the installed package's source/docs in the pub cache and rewrite only the affected calls using the correct API.
```
